## as

### 类型断言

类型断言 (`Type Assertion`)，`TypeScript` 提供的类型强制转换。
因为在某些时候开发者可能比 `TypeScript` 更清楚地知道具体的类型，例如：

```ts
const divElm = document.getElementById('id');
```

`document.getElementById` 默认返回的是较为宽泛的类型 `HTMLElement`，但开发者更清楚地知道获取的类型是更为精确的 `HTMLDivElement`，这时就可以使用类型断言，强制进行类型转换。断言有两种语法形式：

```ts
// as 关键字
const divElm = document.getElementById('id') as HTMLDivElement;

// 尖括号
const divElm = <HTMLDivElement>document.getElementById('id');
```

### 断言的类型要求

断言可以是更为宽泛的类型，也可以是更为狭窄的类型，但是前后两种类型之间必须存在重叠：

```ts
// number 和 string 类型不能充分重叠
// code-error-next-line
const str = 123 as string;
// Error: 类型 "number" 到类型 "string" 的转换可能是错误的，因为两种类型不能充分重叠。

// code-error-next-line
const num = '123' as number;
// Error: 类型 "string" 到类型 "number" 的转换可能是错误的，因为两种类型不能充分重叠。
```

类型断言之后，`TypeScript` 会把该类型作为断言后的类型处理，但是 `TypeScript` 并不会对断言的准确性进行检验：

```ts
const str = {} as string;
// code-error-next-line
str.charAt(0);
// Uncaught TypeError: {}.charAt is not a function
```

`TypeScript` 允许 `str.charAt(0)` 方法的调用，因为是 `string` 类型的合法方法，但在代码运行时会出现错误。
所以断言是比较危险的，开发者必须确保断言的正确性。

## satisfies

`satisfies` 是 TypeScript 4.9 引入的关键字，用于**检验类型是否匹配**，同时**保留推导出的更精确类型**。

### 基本用法

```ts
type Colors = 'red' | 'green' | 'blue';

// 使用类型注解 — 类型被拓宽为 Colors，丢失了具体值
const palette1: Record<Colors, string> = {
  red: '#ff0000',
  green: '#00ff00',
  blue: '#0000ff',
};
// palette1.red 的类型是 string

// 使用 satisfies — 既校验类型，又保留每个属性的字面量类型
const palette2 = {
  red: '#ff0000',
  green: '#00ff00',
  blue: '#0000ff',
} satisfies Record<Colors, string>;
// palette2.red 的类型是 '#ff0000'（字面量类型），而不是 string
```

### satisfies vs as 的核心区别

| 特性       | `as`                    | `satisfies`         |
| ---------- | ----------------------- | ------------------- |
| 类型校验   | ❌ 不做校验，强制转换    | ✅ 校验是否匹配      |
| 类型推断   | 被断言类型完全覆盖       | 保留原始窄类型       |
| 安全性     | 低，可能掩盖错误         | 高，编译时发现问题    |
| 额外属性   | 不报错                   | 报错                |

### 配合 as const 使用

`satisfies` 与 `as const` 组合，可以在保证类型安全的同时获得最精确的字面量类型：

```ts
const routes = {
  home: '/',
  about: '/about',
  user: '/user/:id',
} as const satisfies Record<string, `/${string}`>;

// routes.home 的类型是 '/'（字面量）
// routes.user 的类型是 '/user/:id'（字面量）
// 同时所有值都被校验为 `/${string}` 格式
```

### 典型使用场景

1. **调色板 / 常量映射**：既要有类型安全，又要保留具体值用于自动补全
2. **路由配置**：校验路由格式，同时保留路径字面量
3. **组件 props 默认值**：校验是否符合 Props 类型，同时保留窄类型推导
