`MCP`（`Model Context Protocol`，模型上下文协议）是 Anthropic 推出的开放标准协议，用于**连接 AI 模型与外部工具和数据源**。可以把它理解为 AI 的 "USB 接口"。

## 为什么需要 MCP？

在 MCP 出现之前，让 LLM 调用外部工具的做法是 Function Calling——每个工具、API 的对接都由开发者手动编写适配代码。当工具数量增多时，维护成本急剧上升。

MCP 解决的问题：

```text
# 没有 MCP：每个集成都需要单独适配
LLM → [自定义代码] → API A
LLM → [自定义代码] → API B
LLM → [自定义代码] → 数据库 C

# 有 MCP：统一协议，一次对接，到处复用
LLM → [MCP Client] ─协议→ [MCP Server A]
                   ─协议→ [MCP Server B]
                   ─协议→ [MCP Server C]
```

## MCP 架构

```text
┌─────────────┐     MCP Protocol     ┌──────────────┐
│  MCP Client  │ ◄──────────────────► │  MCP Server   │
│  (AI 宿主)    │    JSON-RPC 2.0     │  (工具/数据源)  │
└─────────────┘                      └──────────────┘
      ▲                                     ▲
      │                                     │
┌─────┴──────┐                      ┌──────┴────────┐
│ Claude App │                      │  本地文件系统   │
│  VS Code   │                      │  数据库         │
│  Cursor    │                      │  API 封装       │
│  自定义应用  │                      │  搜索引擎       │
└────────────┘                      └───────────────┘
```

- **MCP Client**：嵌入在 AI 应用（如 Claude Desktop、VS Code、Cursor 等）中的客户端，负责发现和调用 MCP Server
- **MCP Server**：对外暴露工具和资源的服务端，按 MCP 协议实现

## 核心概念

### Tool（工具）

模型可以调用的函数，类似 Function Calling 中的 function：

```json
{
  "name": "search_docs",
  "description": "在知识库中搜索文档",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "搜索关键词" },
      "limit": { "type": "number", "default": 5 }
    },
    "required": ["query"]
  }
}
```

### Resource（资源）

服务器暴露的只读数据，如文件内容、数据库记录、配置信息等。

### Prompt（提示模板）

服务器提供的预定义 prompt 模板，用户可以快速调用：

```json
{
  "name": "code_review",
  "description": "对指定代码进行 review",
  "arguments": [
    { "name": "language", "description": "编程语言", "required": true },
    { "name": "code", "description": "待审查的代码", "required": true }
  ]
}
```

## 传输方式

MCP 支持两种传输协议：

| 方式 | 说明 | 使用场景 |
| --- | --- | --- |
| `stdio` | 通过标准输入/输出通信 | 本地进程，简单直接 |
| `Streamable HTTP` | 基于 HTTP + SSE（Server-Sent Events） | 远程服务器，兼容性更好 |

```json
// MCP Client 配置示例（Claude Desktop）
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@anthropic-ai/mcp-server-filesystem", "/path/to/data"]
    },
    "remote-server": {
      "url": "https://mcp.example.com/mcp",
      "transport": "streamable-http",
      "headers": {
        "Authorization": "Bearer xxx"
      }
    }
  }
}
```

## 官方 MCP Server

Anthropic 官方提供了多个可直接使用的 MCP Server：

| Server | 功能 |
| --- | --- |
| `@anthropic-ai/mcp-server-filesystem` | 本地文件系统访问 |
| `@anthropic-ai/mcp-server-github` | GitHub API 操作 |
| `@anthropic-ai/mcp-server-postgres` | PostgreSQL 查询 |
| `@anthropic-ai/mcp-server-slack` | Slack 消息管理 |
| `@anthropic-ai/mcp-server-memory` | 持久化知识图谱 |

所有 Server 可在 [github.com/anthropics](https://github.com/anthropics) 查看。

## 自定义 MCP Server

最简单的 Python MCP Server：

```python
# server.py
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("demo-server")

@mcp.tool()
def add(a: int, b: int) -> int:
    """返回两个整数的和"""
    return a + b

if __name__ == "__main__":
    mcp.run(transport="stdio")
```

配置后，模型就能直接调用 `add` 函数进行计算。

## 总结

MCP 的核心价值：**标准化的工具集成协议**。开发者写一次 MCP Server，所有支持 MCP 的 AI 客户端都可以使用，避免了重复造轮子。随着越来越多的应用和工具拥抱这个协议，MCP 正在成为 AI 生态的基础设施。
