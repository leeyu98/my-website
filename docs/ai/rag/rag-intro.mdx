`RAG`（`Retrieval Augmented Generation`，检索增强生成）是目前最主流的 LLM 应用架构之一。
核心思想：**先检索相关知识，再让模型基于这些知识作答**，以解决模型知识陈旧和幻觉问题。

## 为什么需要 RAG？

LLM 存在两个根本问题：

| 问题 | 表现 |
| --- | --- |
| 知识截止 | 训练数据有截止日期，无法回答最新问题 |
| 幻觉 | 对不熟悉的领域会"凭空编造"答案 |

RAG 的思路很简单：**不给模型背百科全书，而是给它一本词典，每次问问题时先查一下。**

## RAG 工作流程

```text
                  ┌─────────────┐
                  │  用户提问    │
                  └──────┬──────┘
                         │
              ┌──────────▼──────────┐
              │  1. Embedding 模型   │
              │     文本 → 向量      │
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  2. 向量数据库       │
              │     相似度检索       │
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  3. 取 Top-K 结果   │
              │     作为上下文注入   │
              └──────────┬──────────┘
                         │
              ┌──────────▼──────────┐
              │  4. LLM 生成回答    │
              │  基于检索到的知识   │
              └─────────────────────┘
```

### 具体步骤

1. **文档切分**：将长文档切成小块（chunk），控制每条在几百 token 以内
2. **向量化**：用 embedding 模型将每个 chunk 转为向量，存入向量数据库
3. **检索**：用户提问时，同样将问题向量化，在向量数据库中做相似度查询，取 Top-K
4. **增强生成**：将检索到的片段拼入 LLM 的 prompt 作为上下文，生成回答

## 关键实现细节

### Chunk 策略

切分方式直接影响检索质量：

| 策略 | 方式 | 适合场景 |
| --- | --- | --- |
| 固定长度 | 按 token 数/字符数切分 | 通用文本 |
| 语义切分 | 按段落或语义边界切分 | 长文档、技术文档 |
| 滑动窗口 | 相邻 chunk 有重叠内容 | 避免上下文断裂 |

```python
# LangChain 示例：按字符切分，重叠 200 字
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    separators=["\n\n", "\n", "。", "，", " "]
)
chunks = splitter.split_text(document)
```

### 检索优化

基本检索容易遗漏相关内容，可以组合多种方式：

- **Hybrid Search**：向量检索 + 关键词检索（BM25），各取所长
- **Re-ranking**：对初步检索结果用更强的模型二次排序，过滤掉噪声
- **Multi-query**：把用户问题改写为多个角度的问题，分别检索后合并

### 检索后处理

```text
请根据以下参考资料回答用户问题。

如果参考资料中没有提到相关信息，
请明确说"根据现有资料，无法回答此问题"，
而不要编造答案。

参考资料：
{检索到的 chunks}

用户问题：
{用户输入}
```

## 技术栈选型

| 层级 | 常见方案 |
| --- | --- |
| 文档加载 | `LangChain` Document Loader、`LlamaIndex` Reader |
| 文档切分 | `LangChain` Text Splitter、自行实现 |
| Embedding | `OpenAI text-embedding-3`、`Voyage AI`、`BGE`（开源） |
| 向量数据库 | `Pinecone`（云）、`Milvus`（开源）、`Chroma`（轻量）、`pgvector`（PostgreSQL 扩展） |
| 编排框架 | `LangChain`、`LlamaIndex`、`Dify`（低代码） |

## 进阶：Agentic RAG

实际上，RAG 不仅仅是在检索文档后把结果给 LLM 用——也可以让 LLM 在需要更多信息时，**自主决定去搜索什么、用什么工具查、查完后怎么整合**，这就是 `Agentic RAG`，更灵活，但也更复杂。

## 总结

RAG 是目前**投入产出比最高**的 LLM 应用模式：实现门槛低，效果提升明显。
核心要点：**chunk 策略和检索质量**决定了 RAG 的上限。
