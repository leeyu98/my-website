`Function Calling`（函数调用）是 LLM 调用外部工具/API 的核心机制。模型不只是生成文本，还能**决定何时调用哪个函数，并生成结构化的调用参数**。

## 工作原理

```text
用户: "北京今天天气怎么样？"

1. LLM 分析 → 需要调用 getWeather 函数
2. 返回函数调用请求:
   { "name": "getWeather", "arguments": { "city": "北京" } }
3. 开发者执行 getWeather("北京")，拿到结果
4. 将结果返回给 LLM → 生成自然语言回复
5. LLM: "北京今天晴，24°C，适合出行。"
```

整个过程由**开发者定义函数列表**，LLM 自主决定是否调用、调用哪个、传什么参数。

## 定义函数（Tool Definition）

以 OpenAI 兼容格式为例：

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "获取指定城市的天气信息",
        "parameters": {
          "type": "object",
          "properties": {
            "city": {
              "type": "string",
              "description": "城市名称，如 北京、上海"
            }
          },
          "required": ["city"]
        }
      }
    },
    {
      "type": "function",
      "function": {
        "name": "search_knowledge_base",
        "description": "在内部知识库中搜索文档",
        "parameters": {
          "type": "object",
          "properties": {
            "query": { "type": "string" },
            "top_k": { "type": "integer", "default": 5 }
          },
          "required": ["query"]
        }
      }
    }
  ]
}
```

## 执行流程

```python
import json

def handle_tool_calls(response):
    messages = [{"role": "user", "content": "北京天气怎么样？"}]

    while True:
        # 1. 调用 LLM
        resp = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
        )

        msg = resp.choices[0].message

        # 2. 无工具调用 → 返回最终回复
        if not msg.tool_calls:
            return msg.content

        # 3. 执行工具调用
        for tool_call in msg.tool_calls:
            func_name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)

            # 实际执行
            result = execute_function(func_name, args)

            # 4. 将结果添加到对话历史
            messages.append(msg)
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": json.dumps(result),
            })
```

## Tool Choice

可以控制 LLM 的工具调用行为：

| 选项 | 行为 |
| --- | --- |
| `"auto"`（默认） | 模型自主决定是否调用工具 |
| `"required"` | 强制至少调用一个工具 |
| `"none"` | 禁止调用工具，只生成文本 |
| `{"type": "function", "function": {"name": "xxx"}}` | 强制调用指定函数 |

## 设计函数的实用技巧

### 1. 描述越清晰，调用越准确

```json
// ❌ 描述模糊
{ "name": "search", "description": "搜索" }

// ✅ 清晰描述用途和限制
{
  "name": "search_products",
  "description": "根据关键词和价格区间搜索商品。仅限在售商品。"
}
```

### 2. 参数使用 enum 约束

```json
{
  "properties": {
    "sort_by": {
      "type": "string",
      "enum": ["price", "rating", "sales", "newest"],
      "description": "排序方式"
    }
  }
}
```

### 3. 善用 required 和 default

把核心参数标记为 `required`，可选参数提供 `default` 值。

### 4. 提供函数选择提示

在 system prompt 中给出何时调用工具的指导：

```text
当用户询问天气、温度相关信息时，使用 get_weather 函数。
如果知识库中包含相关信息，优先使用 search_knowledge_base。
其他情况直接回答即可。
```

## Function Calling vs MCP

| | Function Calling | MCP |
| --- | --- | --- |
| 定义方式 | 代码中硬编码 tool schema | MCP Server 动态提供 |
| 执行 | 开发者自行实现逻辑 | MCP Server 内部封装 |
| 复用性 | 每个项目单独对接 | 一次编写，多客户端使用 |
| 适用场景 | 项目特定的业务逻辑 | 通用工具/数据源连接 |

两者可以组合使用：MCP 提供通用能力层，Function Calling 处理项目特有的深层逻辑。

## 总结

Function Calling 让 LLM 从"能说"变成"能做"。关键要点：
- 清晰描述函数和参数的用途
- 处理 tool call 的完整生命周期（请求 → 执行 → 结果返回）
- 合理设置 tool_choice 控制调用行为
