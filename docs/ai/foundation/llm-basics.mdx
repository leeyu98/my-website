在接触 AI 应用开发时，首先需要理解大语言模型（`LLM`, `Large Language Model`）的几个核心概念。

## Token

`Token` 是模型处理文本的最小单位。一个 token 大约等于：

- **英文**：约 4 个字符或 0.75 个单词
- **中文**：约 1～2 个汉字

举例："Hello, world!" ≈ 4 tokens，"你好世界" ≈ 4 tokens。

Token 的数量决定了：
- **模型输入上限**：上下文窗口（context window）
- **计费单位**：大多数 API 按 token 计费

### Tokenizer

OpenAI 和 Anthropic 都提供了在线分词工具，可以直接计算文本对应的 token 数：

- [OpenAI Tokenizer](https://platform.openai.com/tokenizer)
- [Anthropic Tokenizer](https://console.anthropic.com/tokenizer)

## Context Window（上下文窗口）

模型单次能处理的最大 token 数（输入 + 输出）。不同模型的上下文窗口差异很大：

| 模型 | 上下文窗口 |
| --- | --- |
| Claude Opus 4.8 | 200K |
| Claude Sonnet 5 | 200K |
| GPT-4o | 128K |
| GPT-4.1 | 1M |
| Gemini 2.5 Pro | 1M |

超过上下文窗口会**截断最早的内容**或返回错误，这也是 RAG（检索增强生成）等技术存在的意义。

## Temperature（温度）

控制模型输出的**随机性**，范围通常为 `0.0` ～ `2.0`：

| 值 | 效果 | 适用场景 |
| --- | --- | --- |
| `0.0` ～ `0.3` | 输出确定、一致 | 代码生成、数学推理、数据提取 |
| `0.5` ～ `0.8` | 平衡创造性和准确性 | 日常问答、写作 |
| `0.9` ～ `2.0` | 高度随机、富有创意 | 创意写作、头脑风暴 |

## Top-P（核采样）

另一种控制随机性的方式。设定一个阈值 `P`，模型只从累积概率达到 `P` 的 token 中采样。

```text
Top-P = 0.1  → 只考虑概率最高的 10% token → 非常确定
Top-P = 0.9  → 考虑概率最高的 90% token → 更随机
Top-P = 1.0  → 考虑所有 token → 完全随机
```

:::tip
一般建议**只调 temperature 或 top-p 其中一个**，不要同时调整。
:::

## System Prompt（系统提示）

在对话开始前，预先设定模型的**角色、行为规则、输出格式**。系统提示对模型行为的影响大于用户消息。

```text
System: 你是一个资深 TypeScript 专家。回答问题要简洁，有代码示例。
User: 解释一下 satisfies 关键字。
```

## Embedding（嵌入向量）

将文本转换为高维向量表示，语义相近的文本在向量空间中距离也更近。主要用于：

- **语义搜索**：找到与查询最相关的文档
- **RAG**：检索相关知识后注入到 LLM 对话中
- **聚类与分类**：文本相似度计算

常见的 embedding 模型：`text-embedding-3-small`（OpenAI）、`voyage-3-lite`（Voyage AI）。
